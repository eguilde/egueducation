# Registratură — parity status

This React slice implements tenant-safe registry selection, server-filtered/paginated/sorted list loading, the **Intrare**, **Ieșire** and **MULTIPLU** creation commands, bounded MULTIPLU count, party lookup/selection, department selection, external-number/date and entry/exit timestamps, activity, Document/Dosar selection, and real multipart uploads after creation. It also implements document detail, canonical workflow-state gating with optimistic-concurrency version, workflow history, version display, attachment download, document print and registry export PDF, guarded cancellation, and tenant-scoped administration for people, departments, organizations and registries. Administration now has real PATCH editing for the specialized party fields and for department/organization/registry payloads, including public/private registry visibility.

All currently usable Registratură contracts are surfaced, including specialist party data (birth and legal-registration fields), organization/registry department memberships, active/default policies, and document links gated by the separate `registratura.links.read` and `registratura.links.manage` permissions.

The old metadata-only staging route could never bind file bytes to its database row and therefore created orphaned, non-downloadable records. It is now deliberately deprecated with `410 attachment_upload_required`. The scanned multipart endpoint is the single supported attachment-write contract and is fully wired in this UI. This removal is an integrity correction, not a missing user function.
